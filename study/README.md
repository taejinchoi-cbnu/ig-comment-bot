# 회고

작업하면서 남기는 기록. 프로젝트 문서([`../docs/`](../docs/))가 **"무엇을 어떻게 만드는가"** 라면,
여기는 **"왜 그렇게 결정했고 무엇이 틀렸는가"** 를 남긴다.

목적이 두 가지다.

1. 같은 판단을 다시 할 때 근거를 되찾기 위해
2. **포트폴리오/자소서 서술의 원천.** 결과물보다 판단 과정이 설명할 거리가 된다

## 쓰는 방식

**PAAR 구조** — Problem(문제) · Analysis(분석) · Action(조치) · Result(결과).
마지막에 **면접용 30초 요약**을 붙인다. 자소서·면접에서 그대로 꺼내 쓸 수 있는 형태로 남긴다.

- 파일명 `YYYY-MM-DD-주제.md`, 제목은 증상이나 판단을 서술형으로 (범주명 금지)
- 하루치가 너무 길어지면 `YYYY-MM-DD-1.md` / `-2.md` 로 나눈다. **성격이 다른 지점에서 자른다** — 파일명이 밋밋해지는 대신 H1 제목이 내용을 말한다
- 존댓말. 숫자·명령어 출력·표로 근거를 남긴다
- **잘한 것보다 바뀐 것과 틀린 것을 자세히.** 방향이 바뀐 지점이 가장 값어치 있다
- **안 만들기로 한 것과 그 이유**를 반드시 남긴다. 만든 것보다 설명하기 좋다
- 사실과 판단을 섞지 않는다. 숫자는 숫자로
