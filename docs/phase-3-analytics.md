# Phase 3 — 성과 분석 ★

> **상태**: 대기   |   **선행**: Phase 2
>
> **완료 기준**: 지인이 "이 게시글 효과 있었어?"에 **대시보드만 보고** 답한다.

## 목표

**이게 이 프로젝트의 존재 이유다.**

지인들의 불만은 자동 DM 기능이 아니라 **"효과가 있었는지 알 수가 없다"** 였고,
해외에서도 **매니챗이 분석을 제품 밖으로 밀어냈다** ([`why.md`](./why.md)).
Phase 1~2는 여기 쓸 데이터를 모으기 위한 준비였다.

범위는 세 층이다. 위에서부터 확실하고, 아래로 갈수록 제약이 붙는다.

| 층 | 내용 | 제약 |
|---|---|---|
| A. 우리 데이터 | 퍼널 · `skipReason` · CSV | 없음 |
| B. 반응자 팔로워 여부 | 게시글별 "반응자 중 팔로워 N명" | 대화 성립 후 조회 |
| C. 계정 인구통계 | 팔로워 추이 · 연령/성별/지역 | **100팔로워 이상**, 계정 단위(귀속 불가), 권한 추가 |

---

## A. 우리 데이터 (제약 없음)

### 퍼널
- [ ] 게시글별 `댓글 → DM 발송 → 답장 → 양식 발송` + 각 단계 전환율
- [ ] **대시보드의 각 게시글 줄에 그대로 표시.** 별도 분석 페이지를 만들지 않는다 (원칙 1)
- [ ] 기간 필터 (오늘 / 7일 / 30일 / 전체), 게시글 정렬

```sql
SELECT media_id, type, count(*) AS n, count(DISTINCT igsid) AS people
  FROM events
 WHERE ig_account_id = $1 AND created_at >= $2
 GROUP BY media_id, type;
```

> ⚠️ **이 쿼리를 짜기 전에 고쳐야 할 것이 둘 있다** (Phase 1 §남은 것):
> - 팔로워로 확인된 사람은 **확인 단계를 건너뛰어** `USER_REPLIED` 없이 `FOLLOW_UP_SENT` 가
>   찍힌다 → 답장→양식 전환율이 100% 를 넘는다
> - 팔로워 게이트가 켜져 있으면 게이트에 막힌 건이 `COMMENT_SKIPPED`+`mediaId` 로 남아,
>   같은 댓글이 "발송됨" 과 "발송 안 됨" 에 **동시에 집계된다**

미리 집계 테이블을 만들지 않는다. 이벤트가 수천 건 규모다.

### "왜 DM이 안 갔지?"
- [ ] `COMMENT_SKIPPED` 집계를 게시글별로 노출
- [ ] `skipReason`을 사람 말로 매핑

| `skipReason` | 화면 표시 |
|---|---|
| `SELF_COMMENT` | 본인이 단 댓글이라 보내지 않았어요 |
| `NO_KEYWORD_MATCH` | 설정한 키워드가 댓글에 없었어요 |
| `DUPLICATE` | 이미 보낸 댓글이에요 |
| `CAMPAIGN_DISABLED` | 이 자동 DM이 꺼져 있었어요 |
| `NOT_FOLLOWER` | 팔로워가 아니라서 보내지 않았어요 (게이트를 켠 경우만) |

- [ ] 실패(`FAILED`)도 `errorCode` → "인스타 권한이 없어요" / "댓글이 7일 지났어요"

> 매니챗은 플로우가 안 터지면 리드가 조용히 유실된다는 불만이 있다. **여기가 우리 강점이다.**

### CSV 내보내기
- [ ] 기간 + 게시글 필터 → `events` CSV
- [ ] 컬럼: 시각 · 게시글 · username · 무슨 일 · 사유
- [ ] **본문은 넣지 않는다** ([`architecture.md`](./architecture.md) 개인정보 원칙)
- [ ] **UTF-8 BOM** — 없으면 엑셀에서 한글이 깨진다
- [ ] 체감 가치 대비 구현량이 가장 작은 항목

## B. 반응자 팔로워 여부

인스타 API는 팔로워 목록을 주지 않아서 **아무도 "이 게시글이 팔로워를 몇 명 늘렸나"를 못 만든다.**
그런데 `is_user_follow_business`는 **개인별로** 조회된다 ([`meta-api.md`](./meta-api.md) §7).

> "이 게시글 반응자 41명 중 팔로워 28명 / 비팔로워 13명"

귀속은 못 해도 **게시글 단위 실측은 된다.** 상용 도구가 보여주지 않는 숫자다.

- [x] MESSAGE 핸들러에서 답장 직후 `GET /{IGSID}?fields=is_user_follow_business` 호출
      — 2026-09-04 완료. 팔로워 게이트를 앞당기면서 같이 들어갔고 `Event.isFollower` 에 박제된다
- [x] **결과를 `Event` 행에 그때 기록한다.** 나중에 다시 조회하면 값이 변해 과거 통계가 흔들린다
      — 2026-09-05 완료. `PRIVATE_REPLY_SENT`·`FOLLOW_UP_SENT` 에 `isFollower` 가 박제된다
- [x] 조회 실패는 무시하고 진행 — 이 값 때문에 DM 발송이 막히면 안 된다
      — `context.ts` 의 `checkFollower` 가 절대 던지지 않고 `null` 을 돌려준다
- [ ] 게시글 줄에 `팔로워 28 / 비팔로워 13` 표시

## C. 계정 인구통계

- [ ] 연결 마법사에서 `instagram_business_manage_insights` 권한도 받도록 안내 수정 (Phase 2 재방문)
- [ ] `follower_count` 일별 추이 → 스파크라인, 캠페인 기간 구간 표시
- [ ] `follower_demographics` `breakdown=age|gender|city` → 막대 없이 **표로**
- [ ] `engaged_audience_demographics` — 반응한 사람들의 분포 (팔로워 전체보다 캠페인에 가깝다)
- [ ] 지표는 시간이 지나면 변하므로 **날짜별 스냅샷 테이블에 쌓는다.** 매번 조회하면 과거가 바뀐다

### 반드시 지킬 것

- **100팔로워 미만 계정은 이 지표들이 아예 안 나온다.** 없으면 이 패널을 숨기고
  "팔로워 100명이 넘으면 여기에 표시돼요"를 보여준다. 빈 차트나 에러가 아니라
- **계정 단위라 게시글별 귀속이 불가능하다.** 문구는 **"이 기간에 +47명"** 이지
  "이 게시글이 47명을 데려왔다"가 **아니어야 한다.** 상관관계를 인과처럼 쓰지 않는다

## ★ 지인에게 물어보기

- [ ] 화면을 보여주고 **"이거 보고 뭐가 더 궁금해요?"** 를 묻는다
- [ ] 답을 `진행 기록`에 그대로 적고, 그중 SQL로 답할 수 있는 것부터 만든다
- [ ] 사용자가 5명이라 가능한 일이고, **상용 서비스가 구조적으로 못 하는 부분**이다

## 하지 않을 것

- **LLM 내러티브 요약** → [Phase 4](./phase-4-later.md). 먼저 표와 숫자로 지인 반응을 본다
- **차트 라이브러리** — 원칙 2대로 표와 문장으로 먼저 답한다. 스파크라인 하나는 인라인 SVG로 충분
- **집계 테이블 / 캐시** — `GROUP BY`가 느려지면 그때
- **별도 분석 페이지** — 대시보드 한 화면에서 답한다

## 검증

- [ ] 지인에게 대시보드만 주고 **"지난주 어느 게시글이 제일 잘 됐어요?"**. 설명 없이 답하면 성공
- [ ] "왜 DM이 안 갔어요?"에 대시보드가 답하는지
- [ ] CSV를 엑셀에서 열어 한글이 안 깨지는지
- [ ] 퍼널 숫자가 실제 DM 발송 이력과 일치하는지 수동 대조
- [ ] **100팔로워 미만 계정**으로 열었을 때 C 패널이 깨지지 않고 안내가 뜨는지
- [ ] 팔로워 여부 조회가 실패해도 DM은 정상 발송되는지
