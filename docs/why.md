# 왜 만드는가

> 한 번 읽으면 되는 문서. 작업 중에는 거의 볼 일이 없다.

## 출발점

지인들이 상용 인스타그램 자동 DM 서비스를 쓰면서 말한 불만은 두 가지였다.

1. **쓰기가 어렵다** — 첫 DM 하나를 보내기까지 배워야 할 개념이 너무 많다
2. **통계가 어렵다** — 자동 DM을 걸어놨는데 그게 효과가 있었는지 알 수가 없다

주목할 점은 **"자동 DM 기능이 부족하다"는 말은 없었다**는 것이다.
상용 서비스들은 자동 DM을 이미 잘 한다. 어려운 건 그 앞뒤다.

> **자동 DM은 만드는 물건이 아니라 데이터를 모으는 장치다. 만드는 물건은 "쉬운 사용"과 "쉬운 분석"이다.**

## 목적

수익이 아니다. 지인들에게 직접 쓸 수 있는 서비스를 만들어주고, 그 과정과 결과를 **포트폴리오/자소서**에 쓰는 것이 목적이다.

이 결정이 범위를 크게 줄여준다 — 자세한 영향은 [`meta-api.md`](./meta-api.md)의 Standard Access 항목 참고.

| 항목 | 결정 |
|---|---|
| Meta App Review + 사업자 인증 | **안 간다.** 수 주짜리 최대 리스크 제거 |
| 결제 · 요금제 · 사용량 과금 | **안 만든다.** 원가가 월 $1~2라 청구 근거 자체가 없다 |
| 사용자 수 | Instagram Tester로 초대한 사람만, **최대 25명**. 지인 대상이라 충분 |
| 멀티 계정 데이터 모델 | **유지.** 계정별 격리는 어차피 필요하고, 나중에 하면 전부 갈아엎어야 한다 |

## 한국 시장 조사 (2026-08 기준)

댓글 키워드 → 자동 DM을 **이미 서비스 중인** 한국 업체:

| 서비스 | 운영 | 가격 |
|---|---|---|
| 리틀리 (litt.ly) | 링크인바이오 | **완전 무료** (마케팅 탭 끼워팔기) |
| 소셜비즈 | **NHN DATA** (대기업) | 팔로워 200명 기준 월 5,000원~, 2주 무료 |
| 포크레터 | 소규모 | 무료 / ₩4,900 / ₩16,900 · 9,389+ 크리에이터 |
| Conma | 한국 SaaS | Plus 월 ₩5,900 (크레딧제) |
| 소시안 | 한국 | 무료(월 2회) / 월 2,900원 |
| 인포크 | 한국 | 월 18,900원 |
| 키티챗 · 센드비 · 와이어디 | 한국 | DM 자동화 / 이벤트 추첨 / 자동 DM |

여기에 매니챗도 한국에서 널리 쓰인다.
**한국어 UI를 갖춘 대기업 서비스와 완전 무료 옵션이 동시에 존재한다.** 1인 개발자가 유료로 진입할 자리는 없다.

→ **상용화하지 않는다.** 이 조사는 방향을 바꾸는 근거가 아니라 *경쟁하지 않아도 된다는 확인*으로만 쓴다.

### 한국 시장에서 배운 것 하나

소셜비즈는 **"10분 이내 설정 가능할 정도로 직관적"** 으로 평가받는다.
즉 **"쉬운 사용"은 한국 시장에서 이미 어느 정도 해결되어 있다.**

원칙 1(개념을 늘리지 않는다)은 **설계 제약으로는 유지**하되, **차별점의 무게는 분석 쪽에 실어야 한다.**
"더 쉽게 만들었다"만으로는 소셜비즈를 이길 근거가 없다.

> 참고: 한국 블로그들은 아직 "매니챗 1,000명 무료"라고 쓰고 있는데, 아래처럼 2026년 3월에 25명으로 축소됐다.
> 정보가 갱신되지 않은 상태다.

## 해외 서비스 조사 — 매니챗

평점 자체는 높다 (G2 4.6 / Capterra 4.6). 그런데 불만이 특정 지점에 몰려 있다.

| 유형 | 내용 |
|---|---|
| **과금 모델 원한** | **연락처 수 기준 과금 — 메시지를 보내지 않아도 청구된다.** 스팸·봇 계정까지 카운트. 리스트가 커지면 청구액이 2~3배 |
| **무료 플랜 붕괴** | **2026년 3월 1,000 → 25 연락처로 축소.** 채널 2개, 자동화 4개 제한. 사실상 유료 강제 |
| **분석이 제품 밖에 있다** ★ | 사용자들이 SocialPilot 같은 도구를 따로 붙여 쓴다. **시장 1위가 분석을 사실상 포기했다** |
| 지원·청구 | 해지 후 청구, 환불 곤란, Pro 사용자가 예고 없이 Free로 강등 |
| **신뢰성** | Instagram API 연결 버그, 캠페인 도중 프로필 연결 끊김, **플로우가 안 터지면 리드가 조용히 유실된다** |

마지막 줄이 우리 설계와 정확히 맞물린다.
**SQS + DLQ + `Event` 로그 + `skipReason`** 이 "안 나간 5건, 이유는 키워드 불일치"를 보여준다.
조용히 유실되지 않는다는 것 자체가 기능이다.

## 비어 있는 자리 = 분석

한국·해외 조사가 같은 곳을 가리킨다.

- 한국: 자동 DM은 다들 잘 하고, 지인들의 불만은 **분석**이었다
- 해외: 시장 1위가 **분석을 아예 제품 밖으로 밀어냈다**

우리가 유리한 이유:

- **원천 이벤트를 전부 `Event` 테이블에 갖고 있다.** 퍼널 집계가 SQL `GROUP BY` 한 번
- 상용 서비스는 대시보드가 범용이라 이 퍼널(댓글 → DM → 답장 → 양식)을 그대로 보여주지 않고 내보내기도 제한적이다
- **사용자가 5명이라 직접 물어보고 맞출 수 있다.** 상용 서비스가 구조적으로 못 하는 것
- 인스타 API가 팔로워 목록을 주지 않아 아무도 "게시글이 팔로워를 얼마나 늘렸나"를 못 만드는데,
  **`is_user_follow_business`를 반응자별로 찍으면 "반응자 중 팔로워 비율"은 만들 수 있다**
  ([`meta-api.md`](./meta-api.md) §7). 귀속은 못 해도 실측은 된다

**따라서 분석은 마지막에 붙이는 옵션이 아니라 [Phase 3](./phase-3-analytics.md)의 주인공이고, 이 프로젝트의 존재 이유다.**

## 제품 원칙

새 기능을 넣을지 말지는 이 두 원칙으로 판단한다. 기능을 추가할 때 **가장 먼저 무너지는 부분**이라 명문화해둔다.

### 원칙 1 — 개념을 늘리지 않는다

상용 서비스가 어려운 이유는 기능이 부족해서가 아니라 **배워야 할 개념이 많아서**다.
매니챗은 flow · node · trigger · condition · tag · sequence · keyword group을 이해해야 첫 DM을 보낸다.

**우리 사용자가 배워야 할 개념은 하나다: "게시글 하나 = 자동 DM 하나".**

| 지킬 것 | 금지 |
|---|---|
| 자동 DM 추가 = 입력 필드 **2개** (게시글 URL + 보낼 DM) | 플로우 빌더, 캔버스, 노드 연결 |
| 나머지는 전부 접힌 "고급 설정" (키워드, 1차 문구) | 필수 입력 늘리기 |
| 용어는 사용자 언어로 — "자동 DM", "게시글" | "캠페인", "트리거", "시퀀스"를 화면에 노출 |

내부 코드/DB에서는 `Campaign` 같은 이름을 써도 되지만 **화면에는 나오지 않는다.**

> 판단 기준: 사용자가 새로 배워야 할 개념이 생기면, 기본값으로 숨기거나 만들지 않는다.

### 원칙 2 — 질문에 바로 답하는 화면

숫자를 나열하지 않는다. 지인들이 실제로 묻는 질문을 화면의 구조로 만든다.

| 사용자의 질문 | 답하는 방식 |
|---|---|
| "이 게시글 효과 있었어?" | 게시글별 한 줄: 댓글 N → DM N → 답장 N → 양식 N (+ 전환율) |
| "왜 DM이 안 갔지?" | `COMMENT_SKIPPED` + `skipReason`을 사람 말로 표시 |
| "어떤 게시글이 제일 잘 됐어?" | 게시글 정렬/비교 |
| "엑셀로 보고 싶어" | CSV 내보내기 |

**차트보다 표와 문장이 먼저다.** 막대그래프 하나 없어도 위 4개에 답하면 목적을 달성한다.
